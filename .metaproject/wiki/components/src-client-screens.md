## Overview

The `src/client/screens` module provides three main screen implementations: the chat view (transcript and roster), the archive list (for browsing closed rooms), and the init picker (for connecting to a room or creating one). These screens compose components from src/client/components and handle screen-specific logic like pagination, selection, and modal overlays.

## How it works

Three screens: **chat-view.ts** is the main live room view, rendering transcript on the left and roster on the right (toggling at ROSTER_BREAKPOINT width), handling pagination and key inputs for scrolling/navigation; **archive-list.ts** displays a list of closed rooms from history, allowing selection and reopening; **init-picker.ts** is the entry screen for connecting to a room. Each screen is a class or factory function that owns its layout state and event handlers, delegated to by the main viewer. The chat view is the most complex, managing scroll position, message selection, and live updates.

## Key concepts

**ChatView** — The main screen: renders transcript, roster, and handles all interaction (scroll, select, post message, open help). **ROSTER_BREAKPOINT** — Column width threshold; below it, roster is hidden or toggled. **ArchiveList** — Lists closed rooms from history.jsonl; user can select one to reopen. **archiveRow** — A single row in the archive list (room id, goal, counts, status of log file). **InitPicker** — Entry screen to resolve which room to connect to.

## Main flows

**Render chat view**: Viewer passes room state and transcript page; chat view renders transcript window on left, roster sidebar on right (if wide), status bar above, footer below. **Scroll transcript**: User presses arrow/page keys; chat view updates scroll position and requests new messages from the client if near the end. **Select message**: User presses j/k; chat view highlights a message and may show details in a modal. **Post owner command**: User presses key; chat view opens prompt modal, submits command, awaits response. **Browse archives**: User selects --archive mode; init-picker lists closed rooms from history.jsonl, user selects one, reopens it locally.
