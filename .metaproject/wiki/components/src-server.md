## Overview

The `src/server` module exposes a room log as an MCP server over HTTP. It creates an MCP server with read-only tools for accessing transcript, state, and agent details, and an owner-command posting tool that forwards commands to an optional dispatcher. The module handles HTTP transport binding, session management, writer lease refresh (when a dispatcher is attached), and graceful shutdown.

## How it works

Three layers: **index.ts** defines `createRoomMcpServer`, which registers the four MCP tools (get_state, get_transcript, get_agent_delta, get_agent_detail) on a MCP server and manages the optional owner-command handler; **serve.ts** binds the server to HTTP via `serveMcpOverHttp`, loads and validates the log upfront, acquires a writer lease if dispatching, and refreshes the lease at regular intervals; **owner-queue.ts** holds pending owner commands in a queue; **http-transport.ts** manages HTTP sessions and request routing; **shutdown.ts** coordinates graceful shutdown. All read tools are read-only (no modifications to the log).

## Key concepts

**OwnerCommandQueue** — Holds commands posted by a client, awaiting a dispatcher or settling with an acceptance/refusal. **OwnerCommandStatus** — One of queued (waiting for dispatcher), accepted (dispatcher approved), or refused (dispatcher rejected). **OwnerCommandResult** — The response to a post: a queue entry ID, status, and optional reason from the dispatcher. **ServeHandle** — The result of `serve()`: the bound HTTP address, port, per-room token, and endpoints for session management. **RoomMcpServerOptions** — Configuration: optional owner-command handler (from dispatcher) and owner-command queue (shared across sessions).

## Main flows

**Start server**: `serve()` reads the log to validate it, acquires a writer lease (if a dispatcher is attached and a lease path is provided), binds HTTP via `serveMcpOverHttp` on a random or specified port, and returns the URL and per-room token. **Attach client**: Client connects over HTTP, authenticated by token, receives a session ID; every tool call runs via the session. **Post owner command**: Client calls `room.post_owner_command`; if a handler is attached, it is called immediately; otherwise, the command is queued. **Heartbeat**: Every 5 seconds, the server refreshes its writer lease; if taken over, it closes itself. **Get transcript**: Client calls `room.get_transcript` with an optional since_seq; server calls the tool from src/server/tools and returns messages and metadata.
