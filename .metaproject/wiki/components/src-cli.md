## Overview

The `src/cli` module provides a single, declarative argument parser for all roomyx commands. Instead of hand-rolled scanners (which historically conflated positionals and flags, silently ignored typos, and allowed flags to be overloaded), it uses a spec-driven approach: each command declares its flags with types and descriptions, and the parser validates strictly, offers helpful suggestions for typos, and returns structured results.

## How it works

Two files: **args.ts** defines `parseArgs`, which takes argv, a flag spec, and returns positionals, typed flag values, and a help flag. It validates that all flags match the spec, converts values to the right type, detects unknown flags and suggests corrections via Levenshtein distance, and throws `ArgError` for invalid input; **specs.ts** defines the flag specs for different commands (e.g., `CLIENT_FLAGS` for the client). The parser rejects unknown flags outright and ensures every flag has the type (string, number, or boolean) the command expects, preventing silent misinterpretation.

## Key concepts

**FlagSpec** — A single flag: its type (string/number/boolean) and description. **FlagSpecs** — A map of flag names to their specs. **FlagValues** — Parsed flag results: a typed Record. **ParsedArgs** — The result: positionals (strings), flags (typed values), help (boolean). **ArgError** — Thrown for errors the caller should report to the user (e.g., unknown flag, type mismatch).

## Main flows

**Parse command**: Caller provides argv, spec, command name; parser scans each token as a flag (--name value, --bool) or positional; for each flag, type-converts the value and validates against spec. **Unknown flag**: Parser computes Levenshtein distance to all known flags and suggests the closest one. **Type conversion**: Flags marked "number" are parsed with Number(), "boolean" are true if present, "string" are kept as-is. **Help flag**: If --help or -h is present, parser sets help=true and caller prints usage and exits 0.
