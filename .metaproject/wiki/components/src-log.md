## Overview

The `src/log` module manages the persistence and interpretation of room logs: append-only JSONL files that record the room's state header, transcript messages, and state edits. It handles reading room logs into memory with validation, applying edits to derive current room state, computing per-agent message deltas and details, and writing new room logs and appending messages. The module enforces the append-only contract and provides precise error messages when logs are corrupted or malformed.

## How it works

Three layers orchestrate log access: **write.ts** handles creation (`createRoomLog`) and appending messages (`appendMessages`) using the lockfile mechanism from `src`; **store.ts** reads and parses the log into a `RoomState` object, and derives agent views through `foldEdits` and per-agent queries; **types.ts** and **schema.ts** define the contracts — `MessageEnvelope`, `RoomState`, goal contract structure, and Zod validation schemas. Edits are messages with a `change` field that modify the goal or roster, and are applied in `seq` order after loading. The first line is always a state header and cannot be rewritten; every following line is a message.

## Key concepts

**MessageEnvelope** — A message in the transcript with seq, from, body, optional kind/in_reply_to/change. **RoomState** — Current goal contract, roster, and optional log_path and dispatcherAttached flag. **GoalContract** — Version, goal statement, criteria, and threshold for pass/fail. **RosterEntry** — An agent ID and name. **AgentDelta** — What messages an agent has not seen since a given seq. **AgentDetail** — All messages from a given agent and the last seq they saw. **MessageChange** — The edit payload when kind is an edit kind (goal_edit, add_participant). **foldEdits** — Applies edits in seq order to derive current state from the original header and all messages.

## Main flows

**Create room**: `createRoomLog` writes a state header with initial goal contract and roster, refuses if the file already exists. **Append message**: `appendMessages` checks the schema, allocates a new `seq` under `withLock` from lockfile, appends the serialized message. **Load room**: `loadRoomLog` reads and parses the header and all message lines, applies edits via `foldEdits` to compute current state, returns both. **Get delta**: `getAgentDelta` reads the log, filters messages after an agent's last message (or a caller's cursor), returns what the agent has not seen. **Get detail**: `getAgentDetail` returns all messages from an agent and the last seq they reached.
