## Overview

The `test/log` module contains tests for room log operations: creating logs, appending messages, validating schema compliance, and applying state edits. Tests verify error handling, edit folding, and transcript reading under various conditions including corruption and edge cases.

## How it works

Tests cover: log creation with initial state and roster, message append with schema validation, seq allocation, edit application (goal/roster changes), state folding with multiple edits, transcript reading with filtering, and error messages for malformed logs. Tests create temporary logs, append messages, read them back, and verify state transitions and error cases. Edge cases tested include corrupted JSON, missing fields, and concurrent access patterns.

## Key concepts

**Schema validation** — Zod schemas ensure message and state line structure. **Edit folding** — Applying edits in seq order to compute current state. **Seq allocation** — Incrementing seq under lock to prevent duplicates. **Transcript filtering** — Returning messages after a given seq.

## Main flows

**Create log**: Call createRoomLog with goal and roster, verify header line written. **Append message**: Call appendMessages with body and sender, verify seq incremented and line appended. **Apply edits**: Append goal_edit message with change payload, fold edits to verify goal updated. **Read transcript**: Load log, filter messages by seq, verify order and content.
