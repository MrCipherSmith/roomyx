## Overview

The `test` module holds integration and end-to-end tests for the core CLI, room operations, writer lease management, skill syncing, and room ownership/takeover scenarios. Tests are written in Bun's test format and use utilities for creating test rooms, appending messages, and verifying room state.

## How it works

Tests are organized by feature: cli-room.test.ts exercises the core room create/append operations; cli-room-ownership-e2e.test.ts tests single-writer discipline and takeover scenarios; writer-lease.test.ts validates lease acquisition, refresh, and staleness logic; cli-room-tools.test.ts checks MCP tool responses; bundled-skill-sync.test.ts verifies skill installation; cli-commands.test.ts tests CLI flag parsing and help. Each test imports production modules directly and validates behavior through assertions on return values, file state, or exceptions thrown.

## Key concepts

**Test utilities** — Helpers for creating rooms, appending messages, reading state, and checking liveness. **Fixtures** — Temporary test directories and logs cleaned up after tests. **Assertions** — Bun's test assertions (assert, equals, throws, etc.).

## Main flows

**Create and append test**: Create a test log via createRoomLog, append a message, read the log back, verify seq and message content. **Takeover scenario**: Start a server with a lease, append a message as the server, attempt append from another process (refused), then append --take-over, verify server detects displacement. **MCP tools test**: Create a room, call each tool with various inputs, verify tool output shape and cursor logic. **Skill sync test**: Call syncSkillBundle, verify bundled skill files are installed into project directories.
