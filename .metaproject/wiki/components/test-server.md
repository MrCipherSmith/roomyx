## Overview

The `test/server` module contains tests for the MCP server, owner-command queue, session management, HTTP transport, and shutdown logic. Tests verify tool responses, queue behavior, session lifetime, dispatcher attachment, and graceful shutdown under various scenarios.

## How it works

Tests exercise: MCP tool outputs (state, transcript, agent delta, agent detail), owner-command queue operations (queuing, accepting, refusing), session creation and termination, HTTP transport binding and cleanup, owner command handling with and without attached dispatcher, and shutdown with live sessions. Tests use in-process test rooms, mock HTTP transports, and temporary resources cleaned up after each test.

## Key concepts

**Owner command queue** — FIFO queue of owner commands awaiting dispatcher or settlement. **Session** — An HTTP client connection to the server; each session can call tools independently. **Dispatcher attachment** — Optional handler for owner commands; when attached, server acquires a writer lease. **Shutdown** — Graceful termination of HTTP transport and cleanup of resources.

## Main flows

**Get transcript**: Tool returns messages since a cursor, with has_more and next_seq. **Post owner command**: Client submits command, queued if no dispatcher, or immediately handled if dispatcher attached. **Session lifetime**: Client connects (gets session ID), calls tools, posts commands, disconnects or timeout. **Shutdown**: Server receives shutdown signal, closes HTTP transport, releases writer lease (if held), waits for in-flight requests.
