                          different interpreter" is a bad first impression for security review.     
                                                                                                    
                          Second: `roomyx serve` and `roomyx mcp` open an unauthenticated HTTP port 
                          on loopback. No token, by design (D-06) — they know it, and D-06a shows   
                          real engineering discipline fixing a DNS-rebinding hole they found before 
                          I would have. That's a point in their favor, honestly. But "no auth, ever 
                          is still a permanent line item in any threat model review, not a one-time 
                          fix.                                                                      
                                                                                                    
                          Third, and bigger for me: single maintainer, 0.x versioning, and multiple 
                          releases in the same day. That's not a stability story I can pin a        
                          dependency to. No SLA, no org behind it — when the one maintainer stops,  
                          we're forking a Bun-only MCP server with no support path.                 
                                                                                                    
                          The MCP surface itself is well-scoped (D-16: three read tools, no write
