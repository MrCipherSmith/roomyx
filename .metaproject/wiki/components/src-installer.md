## Overview

The `src/installer` module manages the lifecycle and discovery of rooms: registering active rooms, deregistering them when they close, tracking closed rooms in a history index, and resolving room addresses for connection. It also handles project initialization and skill synchronization. This module is the authoritative record of which rooms are running, where their logs live, and how to reach them.

## How it works

Five layers: **registry.ts** maintains an on-disk registry of running rooms (ID, port, log path, pid, token) under `.roomyx/rooms/registry.json`, protected by lockfile; **history.ts** maintains an append-only index of closed rooms with metadata (goal, participant count, message count) under `.roomyx/rooms/history.jsonl`; **init-plan.ts** and **init-apply.ts** orchestrate project setup and skill installation; **skill-sync.ts** installs the bundled `startup-room` skill into a project; **skill-targets.ts** resolves installation targets for skills. Registry entries are written atomically via temp-then-rename. History entries are appended without locks (append-only safety). Connection resolution delegates to `roomTransport` and checks room liveness via HTTP.

## Key concepts

**RoomRegistryEntry** — A running room: id, port, log path, pid, started timestamp, per-room token. **RoomHistoryEntry** — A closed room: id, log path, goal, participant count, message count, started/closed timestamps. **RoomHistoryRow** — A history entry plus a boolean flag indicating whether the log file still exists. **Liveness** — Possible states: online (responding), offline (no response), or stopped (registry or process evidence it is gone). **LiveAndUnconfirmed** — Tentative liveness (online but requires confirmation via HTTP).

## Main flows

**Start and register**: `serve()` mints a token, binds HTTP, then calls `registerRoom()` which writes the entry under lock to the registry. **Attach client**: Client calls `resolveConnectionUrl` with room ID or auto-detect; module probes the registry, finds the entry, checks liveness via HTTP, and returns the URL and token. **Close room**: Dispatcher calls `deregisterRoom`, which removes the entry from registry and appends a history entry with goal/counts via `archiveRoom`. **List rooms**: `listRooms` reads the registry, checks each room's HTTP liveness, returns a list with status. **Initialize project**: `init()` creates `.roomyx/` directory structure and optionally installs the startup-room skill via `syncSkillBundle`.
