## Overview

The `test/client` module contains unit and snapshot tests for the TUI client, covering screen rendering, message display, key bindings, help overlay, archive browsing, reconnection behavior, and error handling. Tests use mock MCP servers and verify the client's UI output and state transitions.

## How it works

Tests are organized by feature: render.test.ts validates transcript and roster rendering against snapshots; tool-error.test.ts checks error display and recovery; reconnect-rate.test.ts verifies exponential backoff logic; archive-row.test.ts tests closed room list formatting; first-message.test.ts checks first message handling; help-overlay.test.ts validates key binding display. Tests use mock RoomClient and Viewer instances, feeding state changes and verifying output via snapshot comparisons or assertion checks.

## Key concepts

**Snapshot tests** — Compare rendered UI output against stored snapshots to catch rendering regressions. **Mock RoomClient** — A test double that simulates connection state and message flow. **State snapshots** — Captured screen output before and after key inputs.

## Main flows

**Render test**: Create viewer with mock state, call render, compare output to snapshot. **Error display**: Feed a ToolError to viewer, verify error text appears on screen and can be dismissed. **Reconnect test**: Simulate connection drop, verify backoff intervals, verify reconnect success. **Archive browse**: Load history, render list, simulate selection and open action.
